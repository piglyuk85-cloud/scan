### 2.2 Паттерн проектирования

Используется **смешанная архитектура** на базе Next.js App Router:

- **Слои:**
  - **Presentation:** страницы в `app/`, компоненты в `components/`.
  - **Application/API:** Route Handlers в `app/api/*` — тонкий слой валидации и вызова lib.
  - **Domain/Data:** `lib/` — работа с Prisma, преобразование «сырых» моделей в плоский тип `Exhibit`, синглтоны контента (PageContent, GuideContent).

- **Соответствие:** ближе к **упрощённому слоистому подходу** (Layered) с элементами **Feature-based** (exhibits, page-content, guide, gallery). Чёткого разделения на доменные сервисы и репозитории нет: `lib/exhibits.ts` совмещает и запросы к БД, и бизнес-правила (например, getOrCreate для Category/Student/Supervisor/Department).

- **Роутинг:** file-based (App Router), серверные страницы по умолчанию, клиентские компоненты там, где нужен state и браузерные API (`'use client'`).

## 3. Описание компонентов и модулей

### 3.1 Слой данных (lib)

**lib/prisma.ts**  
Singleton `PrismaClient`: в development переиспользуется через `globalThis`, чтобы избежать множества подключений при hot reload. Логирование только `error`/`warn` в dev.

**lib/exhibits.ts**  
- `exhibitInclude` — единый набор связей для выборок (category, student, supervisor.department, mediaResources, gallerySettings).  
- `formatExhibit(raw)` — преобразование записи Prisma в плоский тип `Exhibit` (медиа → modelPath, previewImage, images; JSON-поля technicalSpecs, interestingFacts; gallerySettings → координаты и видимость).  
- Публичные функции: `getExhibits(includePrivate)`, `getExhibitById(id, includePrivate)`, `getExhibitsByCategory`, `searchExhibits`, `getCategories`, `getYears`.  
- Мутации: `createExhibitFromFlat`, `updateExhibitFromFlat` — принимают плоский `Exhibit`, создают/обновляют связанные сущности (Category, Student, Supervisor, Department через getOrCreate), перезаписывают MediaResource и GallerySettings.  
- Поиск в `searchExhibits` выполняется в памяти после `findMany` (без полнотекстового поиска в SQLite).

**lib/pageContent.ts**  
- Одна запись в БД (id = `'singleton'`), JSON в поле `content`.  
- `getPageContent()` — чтение, мерж с дефолтами из `getDefaultContent()` (главная, о проекте, настройки, каталог, экспонат, футер).  
- `savePageContent(content)` — upsert JSON.  
- Типы в `types/pageContent.ts` (HomePageContent, AboutPageContent, SiteSettings, PageContent).

**lib/guideContent.ts**  
- Аналогично синглтон в БД; контент — `GuideContentData` (intro, sections с блоками text/image/faq).  
- `getGuideContent()`, `saveGuideContent()`, `getDefaultGuideContent()` с готовыми разделами руководства.

### 3.2 API (app/api)

- **GET/POST /api/exhibits** — список (с учётом admin) и создание; создание только при авторизации.  
- **GET/PUT/DELETE /api/exhibits/[id]** — один экспонат, обновление, удаление; PUT и DELETE только при авторизации.  
- **GET/PUT|POST /api/page-content** — контент страниц; запись только для роли `super`.  
- **GET/POST /api/guide-content** — публичное чтение; POST — только при `role === 'super'`.  
- **POST /api/upload** — загрузка файлов только для авторизованного админа.  
- **GET /api/storage/[...path]** — отдача файлов из `storage/` с проверкой пути (path traversal), MIME по расширению, Cache-Control.  
- **GET /api/health** — `{ status: 'ok', timestamp }` для healthcheck.  
- **POST /api/auth/login**, **POST /api/auth/logout**, **GET /api/auth/me** — вход по логину/паролю из .env, сессия в HttpOnly cookie.

**Авторизация:** основной способ — подписанная HttpOnly cookie `admin_session` (подпись HMAC-SHA256 по **`JWT_SECRET_KEY`**). Отдельно заголовок **`x-admin-auth`** используется как **API-ключ для системной интеграции** (скрипты, внешние сервисы): значение заголовка сравнивается с **`API_SERVICE_KEY`**; при неверном ключе выполняется задержка 500 мс для защиты от перебора. Роли: `admin` (экспонаты), `super` (контент, руководство, редактор галереи, камера).

### 3.4 Взаимодействие компонентов

- **Поток данных к карточке экспоната:**  
  Страница exhibit → `getExhibitById` (lib) → Prisma → `formatExhibit` → props в `ModelViewer`(modelPath), `QRCodeDisplay`(exhibitId), текстовые блоки.  
- **Каталог:**  
  CatalogPage fetch `/api/exhibits` и `/api/page-content` → локальный state → фильтрация/пагинация → `ExhibitCard` (превью через SafeImage или ModelThumbnail).  
- **Виртуальная галерея:**  
  GalleryPage fetch `/api/exhibits` → фильтр по 3D → VirtualGallery → для каждого экспоната `ExhibitInSpace` с `SafeModelWrapper`(modelPath), клик → router.push(`/exhibit/${id}`).  
- **Админка:**  
  Вход через POST /api/auth/login (пароль только в теле запроса, не хранится на клиенте); сервер выставляет HttpOnly cookie `admin_session`; все последующие запросы к API отправляются с этой cookie; создание/редактирование экспоната → upload файлов → POST/PUT с полным объектом Exhibit; контент и руководство — отдельные формы и API (доступны только для роли super).

## 4. Схема базы данных и потоков данных

### 4.1 Модели Prisma (schema.prisma)

- **Department** — id, name; связь с Supervisor.  
- **Supervisor** — id, name, position?, rank?, departmentId? → Department; exhibits.  
- **Student** — id, name, course?, groupCode?; exhibits.  
- **Category** — id, name (unique); exhibits.  
- **Exhibit** — основная сущность: инвентарный номер, title, description, fullDescription, creationDate, categoryId, studentId, supervisorId, dimensions, currentLocation, isPublic, technicalSpecs (JSON string), interestingFacts (JSON string), timestamps; связи category, student, supervisor, mediaResources, gallerySettings.  
- **MediaResource** — exhibitId, filePath, fileType (image|video|model), isPrimary; одна запись на файл.  
- **GallerySettings** — exhibitId (unique), posX/Y/Z, scale, rotY, visibleInGallery.  
- **PageContent** — id = 'singleton', content (JSON), updatedAt.  
- **GuideContent** — id = 'singleton', content (JSON), updatedAt.

Связи: Exhibit → Category, Student, Supervisor (SetNull onDelete); Exhibit → MediaResource, GallerySettings (Cascade). Индексы по categoryId, studentId, supervisorId, isPublic, exhibitId, name.

### 4.2 Поток данных: от UI до БД

1. **Просмотр каталога:**  
   Браузер → GET /api/exhibits → prisma.exhibit.findMany + include → formatExhibit → JSON → клиент → фильтры/пагинация → отображение.

2. **Создание экспоната:**  
   Админ форма → сбор полей (включая пути к загруженным файлам) → POST /api/exhibits с телом Exhibit → валидация → createExhibitFromFlat → getOrCreate Category/Student/Supervisor/Department → prisma.exhibit.create → MediaResource.createMany, при необходимости GallerySettings.create → ответ с созданным Exhibit.

3. **Загрузка файла:**  
   Форма → POST /api/upload (FormData) → сохранение в storage/models или public/images → ответ { path } → путь подставляется в modelPath/previewImage/images при сохранении экспоната.

4. **Контент страниц:**  
   Редактор (super) → PUT/POST /api/page-content с JSON → savePageContent → upsert page_content. Главная/каталог/экспонат получают тексты через getPageContent() (SSR или отдельный fetch).

5. **Виртуальная галерея:**  
   Позиции хранятся в GallerySettings (posX/Y/Z, scale, rotY, visibleInGallery). Редактор галереи меняет их в state и сохраняет через PUT /api/exhibits/[id] с полным Exhibit; lib при update перезаписывает GallerySettings (delete + create).

## 6. Безопасность и производительность

### 6.1 Безопасность

- **Авторизация:** пароли хранятся только в .env (`ADMIN_PASSWORD`, `SUPER_PASSWORD`); проверка на сервере в POST /api/auth/login. Сессия выдаётся в HttpOnly cookie `admin_session` (подпись HMAC-SHA256 по **`JWT_SECRET_KEY`**), доступ к ней из JavaScript отсутствует. Заголовок **`x-admin-auth`** — API-ключ для системной интеграции; проверка по **`API_SERVICE_KEY`** (отдельно от ключа cookie). При неверном значении заголовка — задержка 500 мс (защита от brute-force).  
- **Защита мутирующих API:** POST/PUT/DELETE экспонатов, POST /api/upload, запись контента страниц и руководства проверяют авторизацию через `getAdminFromRequest` (cookie или заголовок); при отсутствии сессии/ключа возвращается 401 или 403.  
- **Middleware:** в корне проекта `middleware.ts` проверяет авторизацию для путей `/admin/*` (кроме страницы логина `/admin`) и `/api/admin/*`: проверка подписи cookie через Web Crypto API (Edge), при невалидной сессии — редирект на `/admin` для страниц или 401 для API. Это блокирует неавторизованных до рендера страницы и вызова обработчиков.  
- **Path traversal:** в `/api/storage/[...path]` путь склеивается с `process.cwd(), 'storage', ...params.path` и проверяется `filePath.startsWith(storageRoot)` — выход за пределы storage блокируется.  
- **Инъекции:** использование Prisma и параметризованных запросов снижает риск SQL-инъекций.  
- **Контент:** загружаемые файлы сохраняются с новым именем (timestamp), тип задаётся клиентом — желательна проверка MIME/магических байтов и лимиты размера (частично учтено в next.config bodySizeLimit).

### 6.2 Производительность

- **Prisma:** один экземпляр клиента, include для связей без N+1 при выборке экспонатов.  
- **3D:**  
  - В VirtualGallery — отключение теней и снижение качества на мобильных (dpr, precision, shadow-map size), отдельные настройки освещения; `preserveDrawingBuffer: false` где не нужен экспорт.  
  - В ModelViewer/ModelThumbnail — явный `dispose` геометрии и материалов при смене модели и размонтировании; использование `WEBGL_lose_context` при unmount для освобождения GPU.  
- **Рендер миниатюр:** ModelThumbnail с IntersectionObserver загружает 3D только при появлении в viewport; ModelThumbnailRenderer с `frameloop="demand"` и offscreen canvas для генерации превью.  
- **Страницы:** главная и карточка экспоната — SSR; каталог и галерея — клиентский fetch с возможностью кэширования на уровне HTTP (для статики и storage выдан Cache-Control).  
- **Поиск в каталоге:** выполняется в памяти после полной выборки — при большом числе экспонатов целесообразен полнотекстовый поиск или поиск на стороне БД.

## 7. Технические особенности (Deep Dive)

### 7.1 Плоская модель экспоната и нормализованная БД

В приложении используется **плоский DTO** `Exhibit` (types/exhibit.ts): все поля автора, руководителя, категории и медиа приходят в одном объекте. В БД данные нормализованы: отдельные таблицы Category, Student, Supervisor, Department, MediaResource, GallerySettings. Слой `lib/exhibits.ts` выполняет преобразование в обе стороны:

- **Чтение:** `exhibitInclude` + `formatExhibit()` собирают связанные сущности в один объект (category name, supervisor с department, modelPath/previewImage/images из mediaResources, координаты из gallerySettings).  
- **Запись:** `createExhibitFromFlat` / `updateExhibitFromFlat` принимают плоский Exhibit и через getOrCreate по имени/данным находят или создают Category, Student, Supervisor, Department; затем обновляют Exhibit и полностью перезаписывают MediaResource и GallerySettings.

Это даёт удобный контракт для фронта и API (один JSON на экспонат) при сохранении нормализованного хранения и переиспользования сущностей (один студент — много экспонатов).

```ts
// Фрагмент: форматирование и обратное создание связей
export function formatExhibit(exhibit: any): Exhibit {
  const media = exhibit.mediaResources || []
  const modelMedia = media.find((m: any) => m.fileType === 'model')
  // ...
  return { id: exhibit.id, title: exhibit.title, ..., modelPath: modelMedia?.filePath, ... }
}

async function getOrCreateCategory(name: string): Promise<string | null> {
  const existing = await prisma.category.findUnique({ where: { name: name.trim() } })
  if (existing) return existing.id
  const created = await prisma.category.create({ data: { name: name.trim() } })
  return created.id
}
```

### 7.2 Виртуальная галерея: 3D-сцена, управление и устойчивость

**VirtualGallery** (components/VirtualGallery.tsx) — полноценная 3D-сцена (Three.js через React Three Fiber): пол, стены, потолок, экспонаты в пространстве, FirstPersonControls (WASD + мышь), на мобильных — упрощённое освещение и MobileControls.

- **Размещение экспонатов:** если у экспоната заданы galleryPositionX/Y/Z (из GallerySettings), они используются с ограничением по GALLERY_BOUNDS; иначе — авто-сетка по индексу. Масштаб и поворот из galleryScale и galleryRotationY.  
- **Клик по экспонату:** невидимый box вокруг модели ловит pointer; на тач-устройствах различается тап и свайп (время и расстояние между pointerdown и pointerup), чтобы не открывать карточку при вращении камеры.  
- **Устойчивость:** для каждой модели в сцене используется ModelErrorBoundary с повторной попыткой через 3 с; при ошибке показывается заглушка (куб). Загрузка модели вынесена в SafeModelWrapper с dispose сцены при размонтировании и смене modelPath.  
- **Ресурсы:** при unmount страницы вызывается WEBGL_lose_context для освобождения GPU; на мобильных отключаются тени и снижается DPR/precision.

Таким образом, сложность сосредоточена в согласовании данных из БД (позиции/масштаб/поворот), обработке ввода (десктоп/мобильный, клик/тап) и предотвращении утечек памяти и падений при битых моделях.

### 7.3 Загрузка и отображение 3D-моделей: dispose и ErrorBoundary

Работа с GLB/GLTF везде строится по одной схеме: загрузка через `useGLTF`, клонирование сцены, нормализация размера (Box3, scale к целевому max size), центрирование; при размонтировании или смене модели — явный dispose геометрии и материалов (включая текстуры).

- **SafeModel.tsx** — общий компонент для вставки модели в сцену (VirtualGallery, редактор галереи): ModelLoader с useGLTF и useMemo для processedScene, dispose в useEffect cleanup; класс ErrorBoundary с fallback-кубом.  
- **ModelViewer.tsx** — отдельный Canvas для карточки экспоната: после загрузки модели вычисляются центр и размер, камера и OrbitControls подстраиваются (AdaptiveCamera); при unmount — очистка state и при возможности loseContext.  
- **ModelThumbnail / ModelThumbnailRenderer** — миниатюры в каталоге: ленивая загрузка по IntersectionObserver; в ModelThumbnailRenderer — скрытый Canvas с preserveDrawingBuffer и toDataURL для экспорта превью.

Единая функция `disposeScene(scene)` обходит дерево объектов и вызывает dispose у geometry, material и текстур (map, normalMap и т.д.), что критично для долгоживущих SPA и смены моделей без утечек WebGL.

## 8. Выводы: масштабируемость и качество кода

### Масштабируемость

- **Горизонтальная:** приложение stateful только за счёт БД; Next.js и один инстанс приложения можно масштабировать за балансировщиком при использовании общей БД. SQLite не подходит для многопоточного записи с нескольких инстансов — для масштабирования записи нужна замена на PostgreSQL/MySQL и миграции Prisma уже поддерживают смену провайдера.  
- **Данные:** рост числа экспонатов потребует переноса поиска из памяти в БД (полнотекстовый или LIKE/индексы), пагинации на стороне API и, при необходимости, кэширования списков (Redis или HTTP-кэш).  
- **Файлы:** хранение в локальной ФС (storage, public) при нескольких серверах потребует общего хранилища (S3-совместимое или NFS) и единого API отдачи файлов.

### Качество кода (Code Quality)

- **Плюсы:** TypeScript и типы для основных сущностей (Exhibit, PageContent, Guide); разделение API, lib и UI; переиспользование логики экспонатов (exhibitInclude, formatExhibit) и контента; явное освобождение ресурсов 3D и обработка ошибок загрузки моделей; использование единого Prisma-клиента.  
- **Минусы:** дублирование паролей и логики входа в коде; отсутствие проверки прав на части API (POST/PUT exhibits, upload); поиск по экспонатам в памяти; хардкод ролей и строк в нескольких местах; часть логики админки и камеры завязана на localStorage и клиентскую проверку прав.  
- **Рекомендации:** централизованную проверку в API и middleware сохранять; защитить все мутирующие эндпоинты и upload проверкой роли (реализовано); хранить учётные данные и секреты во внешней конфигурации/секретах; при росте данных добавить серверную пагинацию и поиск по БД; рассмотреть вынос констант и ролей в конфиг или константы одного модуля.
