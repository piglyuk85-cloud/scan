# Отчет: Анализ реализации Виртуального зала для пользователей

## 1. Логика перемещения

### Реализация управления камерой

**Используется:** `FirstPersonControls` (кастомная реализация) с поддержкой `PointerLock API`.

**Местоположение:** `components/FirstPersonControls.tsx`

**Механизм работы:**

1. **Десктоп:**
   - Управление: `W/A/S/D` или стрелки клавиатуры
   - Вращение камеры: `PointerLock API` (блокировка курсора) или перетаскивание мышью с зажатой левой кнопкой
   - Скорость движения: `8.0` единиц в секунду (фиксированная)
   - Высота камеры: **жестко зафиксирована на `1.6` единиц** (без bounds) или ограничена границами зала

```272:315:components/FirstPersonControls.tsx
  useFrame((state, delta) => {
    if (!isMountedRef.current) return

    const forward = Number(moveForward.current) - Number(moveBackward.current)
    const right = Number(moveRight.current) - Number(moveLeft.current)
    
    if (forward === 0 && right === 0) {
      return
    }

    const moveSpeed = 8.0
    const speed = moveSpeed * delta

    if (forward !== 0) {
      moveVector.current.setFromMatrixColumn(camera.matrix, 2)
      moveVector.current.multiplyScalar(-forward * speed)
      camera.position.add(moveVector.current)
    }

    if (right !== 0) {
      moveVector.current.setFromMatrixColumn(camera.matrix, 0)
      moveVector.current.multiplyScalar(right * speed)
      camera.position.add(moveVector.current)
    }

    if (bounds) {
      camera.position.x = Math.max(
        bounds.minX + 1,
        Math.min(bounds.maxX - 1, camera.position.x)
      )
      camera.position.z = Math.max(
        bounds.minZ + 1,
        Math.min(bounds.maxZ - 1, camera.position.z)
      )
      camera.position.y = Math.max(
        bounds.minY,
        Math.min(bounds.maxY, camera.position.y)
      )
    } else {
      if (camera.position.y !== 1.6) {
        camera.position.y = 1.6
      }
    }
  })
```

2. **Мобильные устройства:**
   - Управление: виртуальные кнопки (`MobileControls.tsx`)
   - Вращение: тач-жесты или гироскоп (опционально)
   - Высота: фиксирована на `1.6` единиц

### Проверка коллизий

**❌ КОЛЛИЗИИ НЕ РЕАЛИЗОВАНЫ**

**Текущая реализация:**
- Используется только **ограничение границами зала** (`CameraBounds` компонент)
- Камера не может выйти за пределы `GALLERY_BOUNDS` (minX: -24, maxX: 24, minZ: -24, maxZ: 24, minY: 0.5, maxY: 7)
- **Пользователь может проходить сквозь стены и экспонаты**

**Проблемы:**
- Нет физики (например, `cannon.js`, `rapier`, `ammo.js`)
- Нет проверки пересечения с геометрией стен и экспонатов
- Камера может "проваливаться" в пол при быстром движении
- Нет плавного скольжения вдоль стен при касании

## 2. Система освещения и окружения

### Конфигурация освещения

**Используется:** Комбинация `ambientLight`, `directionalLight`, `pointLight`, `spotLight` + `Environment` preset.

**Местоположение:** `components/VirtualGallery.tsx` (строки 722-766)

**Десктоп (полная конфигурация):**
- `ambientLight`: интенсивность `0.35`, цвет `#fff8e1`
- `directionalLight` (основной): позиция `[10, 10, 5]`, интенсивность `1.2`, **тени включены** (`castShadow: true`), размер shadow map: `2048x2048`
- `directionalLight` (дополнительный): позиция `[-10, 8, -5]`, интенсивность `0.6`
- `pointLight` (центральный): позиция `[0, 6.3, 0]`, интенсивность `2.5`, расстояние `42`, затухание `decay: 2`
- `pointLight` (4 угловых): интенсивность `0.9` каждый, расстояние `32`
- `spotLight`: позиция `[0, 5, 0]`, угол `Math.PI / 2.2`, интенсивность `2.0`, **тени включены**
- `pointLight` (2 дополнительных): позиция `[0, 4.5, ±15]`, интенсивность `0.5`
- `Environment preset="sunset"` (HDR окружение)

**Мобильные устройства (упрощенная конфигурация):**
- `ambientLight`: интенсивность `0.5`
- `directionalLight`: интенсивность `0.8`, **тени отключены** (`castShadow: false`), shadow map: `512x512`
- `pointLight` (3 источника): меньшая интенсивность
- `Environment` **отключен** (экономия GPU)

### Нагрузка на GPU

**Десктоп:**
- **Shadow maps:** 2 источника с тенями (directional + spotLight), разрешение `2048x2048` = **8 МБ VRAM** на каждый источник
- **Environment (HDR):** загружается пресет "sunset" (обычно 1-4 МБ текстуры)
- **Общее количество источников света:** 9 (ambient не считается)
- **Оценка нагрузки:** Средняя-высокая (особенно при большом количестве экспонатов, отбрасывающих тени)

**Мобильные устройства:**
- **Shadow maps:** отключены (`shadows={false}` в Canvas)
- **Environment:** отключен
- **Общее количество источников света:** 4
- **Оценка нагрузки:** Низкая-средняя

**Оптимизации:**
- ✅ Разные конфигурации для мобильных и десктоп
- ✅ Отключение теней на мобильных
- ✅ Уменьшение разрешения shadow maps на мобильных (если бы были включены)
- ❌ Нет статических lightmaps (предвычисленное освещение)
- ❌ Нет baked shadows (запеченные тени в текстурах)

### Raycaster

**❌ RAYCASTER НЕ ИСПОЛЬЗУЕТСЯ**

- Взаимодействие основано на **pointer events** (встроенные в React Three Fiber)
- Нет ручного `Raycaster` для проверки пересечений на каждом кадре
- Это **хорошо** для производительности, но ограничивает возможности (например, нельзя определить, на какой именно части модели кликнули)

**Проблемы:**
- ❌ Нет hover-эффектов (подсветка при наведении)
- ❌ Нет визуальной обратной связи перед кликом
- ❌ HTML-лейбл может не отображаться из-за `display: 'none'` в стилях
- ⚠️ Расчет расстояния выполняется для всех экспонатов каждый кадр (O(n) операций, где n = количество экспонатов)

## 4. Оптимизация рендеринга

### LOD (Level of Detail)

**❌ LOD НЕ РЕАЛИЗОВАН**

- Все модели загружаются и рендерятся в полном качестве независимо от расстояния
- При большом количестве экспонатов это может серьезно нагружать GPU

**Рекомендация:** Использовать `@react-three/drei` компонент `Detailed` или `LOD` для упрощения моделей на расстоянии.

### InstancedMesh

**❌ INSTANCEDMESH НЕ ИСПОЛЬЗУЕТСЯ**

- Каждый экспонат рендерится как отдельный объект
- Повторяющиеся элементы интерьера (панели, молдинги, плинтусы) создаются через `.map()` и рендерятся как отдельные `mesh`

**Проблема:** При большом количестве повторяющихся элементов (например, 20 панелей) создается 20 отдельных draw calls вместо 1 instanced draw call.

### Frustum Culling

**✅ АВТОМАТИЧЕСКИ ВКЛЮЧЕНО**

- Three.js автоматически выполняет frustum culling (отсечение объектов вне видимой области камеры)
- Это встроенная оптимизация, не требует дополнительной настройки

**Однако:**
- ❌ Нет явной оптимизации для объектов за стенами (occlusion culling)
- ❌ Нет отложенной загрузки моделей по расстоянию (все модели загружаются при монтировании сцены)

### Другие оптимизации

**Реализовано:**
- ✅ `Suspense` для асинхронной загрузки моделей
- ✅ `ErrorBoundary` для обработки ошибок загрузки
- ✅ Разные настройки Canvas для мобильных (`dpr`, `antialias`, `shadows`)
- ✅ Очистка ресурсов при размонтировании (`disposeScene` в `SafeModel.tsx`)

**Не реализовано:**
- ❌ Отложенная загрузка моделей (lazy loading по расстоянию)
- ❌ Приоритизация загрузки (сначала видимые экспонаты)
- ❌ Упрощение геометрии для далеких объектов
- ❌ Объединение геометрии для статичных элементов интерьера
