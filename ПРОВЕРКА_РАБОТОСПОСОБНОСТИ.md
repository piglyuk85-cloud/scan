# Проверка работоспособности после настройки безопасности и атомарности

## 1. Подготовка окружения

1. **Скопируйте переменные в `.env`** (если ещё не сделано):
   ```bash
   # Минимум для запуска:
   DATABASE_URL="file:./prisma/dev.db"
   JWT_SECRET_KEY="ваш-секрет-не-менее-16-символов"
   API_SERVICE_KEY="ваш-api-ключ-не-менее-16-символов"
   ADMIN_PASSWORD="пароль-для-логина-admin"
   SUPER_PASSWORD="пароль-для-логина-super"
   ```

2. **Примените миграции и при необходимости заполните БД:**
   ```bash
   npm run db:generate
   npm run db:migrate
   # опционально: npm run migrate:data   или  npm run db:studio и ручное добавление
   ```

3. **Запустите приложение:**
   ```bash
   npm run dev
   ```
   Откройте в браузере: http://localhost:3000

---

## 2. Проверка авторизации и middleware

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 2.1 | Открыть http://localhost:3000/admin | Страница логина (форма «Логин» / «Пароль»). |
| 2.2 | Открыть http://localhost:3000/admin/gallery **без входа** | Редирект на `/admin` (страница логина). |
| 2.3 | Ввести логин `admin`, пароль из `ADMIN_PASSWORD` → Войти | Переход в админ-панель, видны разделы «Экспонаты»; разделов «Контент страниц», «Руководство», «Редактор галереи» нет. |
| 2.4 | Выйти, войти с логином `super` и паролем из `SUPER_PASSWORD` | Видны все разделы, включая «Контент страниц», «Руководство», ссылка «Редактор галереи». |
| 2.5 | В том же сеансе открыть http://localhost:3000/admin/gallery | Страница редактора галереи (без редиректа). |
| 2.6 | Выйти, снова открыть /admin/gallery | Редирект на `/admin`. |

**Проверка API без cookie (опционально):**  
Скрипт или Postman: запрос к защищённому API с заголовком `x-admin-auth: <значение API_SERVICE_KEY>`. Должен вернуть данные (например, GET /api/exhibits — список с приватными). Без заголовка и без cookie — для мутирующих методов 401.

## 3. Проверка операций с экспонатами (атомарность и файлы)

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 3.1 | Войти как admin или super → Экспонаты → «Добавить работу» | Открывается форма создания. |
| 3.2 | Заполнить обязательные поля (название, описание, категория), при желании загрузить изображение и 3D-модель → Сохранить | Экспонат появляется в списке; карточка открывается, медиа отображаются. |
| 3.3 | Редактировать этот экспонат: изменить название, заменить/добавить изображение или модель → Сохранить | Изменения сохраняются; старые файлы, которые больше не привязаны к экспонату, удаляются с диска только после успешного сохранения в БД (проверить папки `storage/models` и `public/images` при необходимости). |
| 3.4 | Удалить экспонат | Экспонат исчезает из списка; запись в БД удалена. Файлы на диске при необходимости можно чистить отдельно (сейчас при обновлении удаляются только «старые» медиа, не используемые в новом наборе). |

При сбое во время сохранения/обновления в консоли сервера должны появляться сообщения вида:
- `[exhibits] createExhibitFromFlat: ошибка транзакции` или  
- `[exhibits] updateExhibitFromFlat: ошибка транзакции`  
с указанием `exhibitId` и деталями ошибки.

## 4. Быстрая проверка через консоль браузера (на странице /admin после входа)

- **Сессия:** после входа перезагрузите страницу — вы должны остаться в админке (cookie `admin_session` подхватывается).
- **Роль в навигации:** при входе как `super` в шапке должна быть ссылка «Камера» (или пункт из настроек контента); при входе как `admin` — нет.

---

## 5. Если что-то пошло не так

- **Ошибка «JWT_SECRET_KEY must be set»** — в `.env` задан `JWT_SECRET_KEY` длиной не менее 16 символов.
- **Редирект на /admin при открытии /admin/gallery после входа** — очистите cookie для localhost или проверьте, что вход выполнен под `super`.
- **401 при запросах к API из админки** — запросы идут с тем же доменом; cookie отправляются автоматически. Проверьте, что вы действительно вошли (есть cookie `admin_session`).
- **Транзакция откатывается** — смотрите вывод `console.error` в терминале, где запущен `npm run dev`; там будет шаг (exhibit/media/gallerySettings) и текст ошибки Prisma или БД.

После прохождения пунктов 2 и 3 можно считать, что безопасность (вход, middleware, два ключа) и атомарность операций с экспонатами работают корректно.
