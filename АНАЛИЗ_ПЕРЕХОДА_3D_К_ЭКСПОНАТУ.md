# Анализ механизма перехода от 3D-модели к детальной информации об экспонате

## 1. Механизм клика

### Текущая реализация: **Невидимый хитбокс (Invisible Hitbox)**

**Местоположение:** `components/VirtualGallery.tsx`, компонент `ExhibitInSpace` (строки 140-209)

**Механизм:**
- Используется **невидимый mesh** с `onPointerDown` и `onPointerUp` событиями
- Хитбокс: `<boxGeometry args={[3, 3, 3]} />` с `opacity={0}` и visible={false}`
- Позиционирование: `position={[0, 1, 0]}` (высота 1 единица от центра экспоната)

**Обработка событий:**

**Десктоп:**
```typescript
onPointerDown={(e) => {
  e.stopPropagation()
  if (document.pointerLockElement) {
    document.exitPointerLock() // Разблокировка PointerLock
  }
  setTimeout(() => {
    onClick() // Вызов обработчика с задержкой 100ms
  }, 100)
}}
```

**Мобильные устройства:**
```typescript
onPointerDown - запоминает позицию и время касания
onPointerUp - проверяет:
  - Длительность тапа < 220ms (MAX_TAP_DURATION)
  - Расстояние движения < 8px (MAX_TAP_MOVE)
  - Если условия выполнены → exitPointerLock() + onClick()
```

**Проблемы:**
- ❌ **Нет Raycaster** - клик определяется только по пересечению с хитбоксом
- ❌ **Фиксированный размер хитбокса** (3x3x3) - не адаптируется под размер модели
- ❌ **Задержка 100ms** - может создавать ощущение "залипания"
- ⚠️ **Дублирование логики** - отдельная обработка для мобильных и десктопа

## 2. Маршрутизация

### Текущая реализация: **URL-навигация через Next.js Router**

**Местоположение:** `components/VirtualGallery.tsx`, функция `handleExhibitClick` (строки 668-681)

**Механизм:**
```typescript
const handleExhibitClick = useCallback(
  (exhibitId: string) => {
    router.push(`/exhibit/${exhibitId}`)
  },
  [router]
)
```

**Что происходит:**
1. Клик на экспонат → вызов `onClick()`
2. `handleExhibitClick(exhibit.id)` → `router.push('/exhibit/{id}')`
3. **Полная перезагрузка страницы** (Next.js App Router navigation)
4. Переход на страницу `app/exhibit/[id]/page.tsx`

**Особенности:**
- ✅ Используется стандартная навигация Next.js
- ✅ URL меняется, можно делиться ссылками
- ❌ **Нет модального окна** - полная смена страницы
- ❌ **Нет анимации перехода** - резкий переход
- ❌ **Нет сохранения позиции камеры** - при возврате начинаем заново

## 3. Состояние и передача данных

### Текущая реализация: **URL-параметры + Server-Side Fetching**

**Местоположение:** `app/exhibit/[id]/page.tsx` (строки 18-31)

**Механизм передачи данных:**

1. **В VirtualGallery:**
   - Данные экспонатов передаются через props: `exhibits: Exhibit[]`
   - Загружаются на странице `/gallery` через API: `fetch('/api/exhibits')`
   - Фильтруются только экспонаты с 3D моделями

2. **На странице экспоната:**
   ```typescript
   // Server Component - загрузка на сервере
   const exhibit = await getExhibitById(params.id, isAdmin)
   const allExhibits = await getExhibits(false) // Для навигации
   ```

**Проблемы:**
- ❌ **Дублирование запросов** - данные загружаются дважды:
  1. В VirtualGallery (для отображения в 3D)
  2. На странице экспоната (для детальной информации)
- ❌ **Нет глобального состояния** - нет Zustand/Redux/Context
- ❌ **Нет кэширования** - каждый переход = новый запрос к БД
- ⚠️ **Загрузка всех экспонатов** на странице деталей только для навигации (prev/next)

## 4. Плавность перехода

### Текущая реализация: **Частичная блокировка PointerLock**

**Местоположение:** `components/VirtualGallery.tsx` (строки 158-159, 190-191)

**Что происходит:**

**При клике на экспонат:**
```typescript
if (typeof document !== 'undefined' && document.pointerLockElement) {
  document.exitPointerLock() // Разблокировка перед переходом
}
```

**Проблемы:**
- ✅ PointerLock разблокируется перед переходом
- ❌ **Нет анимации камеры** - нет подлета к объекту
- ❌ **Нет плавного перехода** - резкая смена страницы
- ❌ **Нет сохранения контекста** - позиция камеры теряется
- ❌ **Задержка 100ms** перед переходом может создавать ощущение "залипания"

**Отсутствует:**
- Анимация подлета камеры к экспонату
- Fade-in/fade-out эффекты
- Плавное масштабирование
- Сохранение позиции камеры для возврата

## 5. Костыли и дублирование

### ❌ КРИТИЧЕСКАЯ ПРОБЛЕМА: Дублирование запросов к API

**Проблема 1: Двойная загрузка данных экспоната**

**В VirtualGallery:**
```typescript
// app/gallery/page.tsx (строки 11-22)
const response = await fetch('/api/exhibits')
const data: Exhibit[] = await response.json()
const exhibitsWithModels = data.filter((ex) => ex.has3DModel && ex.modelPath)
```

**На странице экспоната:**
```typescript
// app/exhibit/[id]/page.tsx (строка 31)
const exhibit = await getExhibitById(params.id, isAdmin)
// + загрузка всех экспонатов для навигации (строка 41)
const allExhibits = await getExhibits(false)
```

**Результат:**
- При клике на экспонат данные уже есть в памяти (VirtualGallery)
- Но при переходе происходит **новый запрос к БД** через `getExhibitById()`
- **Дополнительно загружаются ВСЕ экспонаты** только для prev/next навигации

**Проблема 2: Неэффективная навигация**

```typescript
// Загружаются ВСЕ экспонаты только для определения prev/next
const allExhibits = await getExhibits(false)
const currentIndex = allExhibits.findIndex((e) => e.id === exhibit.id)
```

**Проблема 3: Отсутствие кэширования**

- Нет React Query / SWR
- Нет кэша на уровне Next.js
- Каждый переход = новый запрос к Prisma

## Рекомендации по улучшению

### 1. Механизм клика
- ✅ Использовать **Raycaster** для точного определения клика по модели
- ✅ Динамический размер хитбокса на основе bounding box модели
- ✅ Убрать задержку 100ms или сделать её опциональной

### 2. Маршрутизация
- ✅ Рассмотреть **модальное окно** (Overlay) вместо полной смены страницы
- ✅ Использовать Next.js `<Link>` с `shallow routing` для плавных переходов
- ✅ Сохранять позицию камеры в sessionStorage для возврата

### 3. Состояние
- ✅ Внедрить **Zustand** или **Context API** для глобального состояния
- ✅ Передавать данные экспоната через состояние, а не только через URL
- ✅ Использовать **React Query** для кэширования и синхронизации

### 4. Плавность перехода
- ✅ Добавить анимацию подлета камеры к экспонату перед открытием
- ✅ Fade-in/fade-out эффекты
- ✅ Плавное масштабирование модели

### 5. Оптимизация запросов
- ✅ Использовать **React Query** с кэшированием
- ✅ Передавать данные экспоната через состояние при переходе
- ✅ Загружать prev/next экспонаты через отдельный API endpoint (не все сразу)
- ✅ Использовать Next.js кэширование для статических данных
